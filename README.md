# 🎩 Lounge

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE.md)

> *Good Games Only.*

**Lounge 0.1.1 Beta** — Discord-бот для организации настольных игр в текстовых каналах. Бот собирает игроков, раздаёт роли в личных сообщениях, ведёт фазы Мафии и сохраняет статистику.

Бот доступен публично, но находится в стадии Beta. Голосовые каналы можно использовать для общения игроков; бот пока не подключается к ним и не управляет голосовым обсуждением.

## Возможности

### Мафия

- **Lite: 4–6 игроков.** Мафия и мирные жители.
- **Full: 7–15 игроков.** Мафия, мирные жители, комиссар и доктор.
- Цикл партии: ночь → день → тайное голосование → проверка победы.
- Роли и ночные действия через ЛС, голосование через кнопки в канале игры.
- Ночь длится до 2 минут, обсуждение — до 5 минут, голосование — до 1 минуты. Ночь и голосование могут завершиться раньше после получения всех необходимых действий; ведущий может ускорить обсуждение.
- Доктор может лечить себя, но не две ночи подряд.
- Если хотя бы одну роль не удалось доставить, старт отменяется. После открытия ЛС нужно создать новое лобби; роли распределятся заново.

### Лобби, профили и фишки

- Кнопки присоединения, выхода, старта и отмены лобби.
- Лобби закрывается после 15 минут бездействия; проверка выполняется раз в минуту.
- Ведущий может отменить начавшуюся Мафию без записи результата и начисления фишек.
- За завершённую Мафию победители получают **15 фишек**, проигравшие — **3 фишки**.
- Профили показывают число партий, побед и фишек. `/top` выводит рейтинг текущего сервера.
- Статистика и фишки разделены по Discord-серверам (`guild_id`).

**Бункер и Custom пока являются заглушками:** они доступны в выборе лобби, но полноценные правила и завершение партий для них не реализованы. Глобального рейтинга и настраиваемых параметров серверов пока нет.

## Команды

| Команда | Описание |
| --- | --- |
| `/lounge` | Справка о боте. |
| `/game-start` | Создать лобби и выбрать режим. |
| `/game-cancel` | Ведущему: отменить лобби или начавшуюся Мафию. |
| `/profile` | Свой профиль или профиль выбранного игрока. |
| `/top` | Топ игроков текущего сервера по фишкам. |
| `/active` | Лобби и партии Мафии на текущем сервере. |
| `/ping` | Задержка соединения бота с Discord. |

## Исправления 0.1.1 Beta

- Кнопки Мафии проверяют текущую партию, фазу и раунд; устаревшие действия отклоняются.
- Добавлена защита от повторного запуска переходов фаз.
- При ожидании ночных действий учитываются только живые мафиози.
- Исправлено самолечение доктора с ограничением на последовательные ночи.
- Начавшаяся Мафия отображается в `/active` и отменяется ведущим через `/game-cancel`.
- При отмене партии останавливаются её таймеры; ошибка отправки финального сообщения не оставляет завершённую игру зарегистрированной.

## Локальный запуск

Требуется **Python 3.12+** (Nextcord 3.0.1 требует Python 3.12 или новее). Проверки проекта выполнялись на Python 3.12.

1. Клонируйте репозиторий и установите зависимости:

   ```bash
   git clone https://github.com/Sozdatel2/Loungee.git
   cd Loungee
   python -m venv .venv
   ```

   Linux/macOS:

   ```bash
   .venv/bin/python -m pip install -r requirements.txt
   ```

   Windows PowerShell:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Создайте приложение и бота в [Discord Developer Portal](https://discord.com/developers/applications). В разделе **Bot → Privileged Gateway Intents** включите **Server Members Intent** и **Message Content Intent**, которые запрашивает текущий код. Если Discord требует одобрения этих intents для вашего приложения, получите его перед запуском.

3. Пригласите бота на тестовый сервер со scopes `bot` и `applications.commands`. В игровом канале разрешите просмотр канала, отправку сообщений и встраивание ссылок (embeds). Участники должны разрешить личные сообщения от бота.

4. В корне проекта создайте файл `.env`:

   ```dotenv
   DISCORD_TOKEN=ваш_токен_бота
   ```

   Можно передать `DISCORD_TOKEN` через переменные окружения вместо файла. `.env` исключён из Git: не публикуйте токен в репозитории, логах или сообщениях.

5. Запускайте из корня проекта:

   ```bash
   .venv/bin/python main.py
   ```

   На Windows используйте `.\.venv\Scripts\python.exe main.py`.

Дождитесь сообщений об инициализации БД, загрузке всех трёх модулей и синхронизации команд. Затем проверьте `/ping` и тестовую партию на своём сервере. Синхронизация глобальных команд не гарантирует их мгновенного появления во всех клиентах Discord.

При работе через обязательный сетевой прокси нужна отдельная настройка: текущий код не передаёт параметр `proxy` в Nextcord. Одного `HTTPS_PROXY` недостаточно; подключение в такой среде пока не проверено.

## Хранение данных и ограничения Beta

- SQLite создаётся автоматически в `data/lounge.db` относительно рабочей директории. Каталог `data/` исключён из Git; сохраняйте его на постоянном диске и делайте резервные копии.
- Активные партии находятся в памяти и **не восстанавливаются после перезапуска**. Избегайте перезапуска во время игры.
- Ошибки сети, прав Discord или БД пока могут прервать игровую фазу. Автоматическое восстановление таких партий ещё не реализовано.
- История завершённой Мафии и награды сохраняются одной транзакцией. Уникальный `game_id` защищает от повторного начисления при повторной записи той же партии. Если сохранение не подтверждено, итоговое сообщение предупреждает об ошибке; автоматического восстановления несохранённых результатов после перезапуска пока нет.
- При первом запуске обновлённого кода схема SQLite дополняется полем `game_id` и уникальным индексом; старые записи сохраняются. Перед обновлением делайте резервную копию `data/lounge.db`.
- Команды доступны после успешной подготовки БД, загрузки всех модулей и синхронизации. При ошибке инициализации бот отключается; после устранения причины его нужно запустить заново.
- Для игры используйте серверные текстовые каналы; работа игровых команд в ЛС не предназначена для этого сценария.

## Проверки для разработки

Из корня репозитория:

```bash
.venv/bin/python -m pip check
.venv/bin/python -m unittest discover -s tests -v
```

На Windows замените путь к Python на `.\.venv\Scripts\python.exe`.

Добавлены 44 регрессионных теста: устаревшие кнопки, повторные переходы, ночные действия, самолечение, отмена партии, доставка ролей, очистка лобби, сбои фаз и инициализации. Тесты SQLite на временных базах проверяют миграцию схемы, откат при сбое начисления, отмену операции и защиту от повторных и одновременных записей. Discord-взаимодействия имитируются; токен не требуется. Эти проверки не заменяют реальную партию в Discord.

## Автоматические проверки (CI)

Workflow `.github/workflows/ci.yml` запускается при коммитах в `main`, Pull Request в `main` и вручную через вкладку **Actions → Python tests → Run workflow** на GitHub.

На Ubuntu с Python 3.12 он устанавливает зависимости из `requirements.txt`, выполняет `pip check` и запускает регрессионные тесты. Discord-токен не нужен: рабочий бот не запускается, соединение с Discord не устанавливается, тесты БД используют временные файлы. CI не выполняет развёртывание и не перезапускает бота.

Результат и логи каждого шага доступны во вкладке **Actions** и в проверках коммита или Pull Request. Ошибка проверки сама по себе не запрещает прямую запись в `main`: для обязательного прохождения CI нужна отдельная настройка защиты ветки на GitHub.
